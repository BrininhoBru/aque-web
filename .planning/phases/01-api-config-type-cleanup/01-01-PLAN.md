Non-goal: this phase changes ZERO rendered output. No template, style, layout, copy, or interaction behavior may change. If a diff touches an `.html` file or a `styles:` array, it is out of scope.

No interface wrapper is created for the environment object: `npm run build` defaults to the production configuration, which compiles `environment.prod.ts` in place of `environment.ts`, so any shape drift between the two files breaks the build at every consumer. A hand-written `Environment` interface would be a second source of truth for a one-field object.

## Types verified against the installed libraries (do not substitute)

Both signatures below were type-checked against this repo's `node_modules` before this plan was written. Do not swap in a differently-named type from memory.

- Signal Forms (`@angular/forms/signals`, Angular 21.2.6): `form<TModel>(model: WritableSignal<TModel>, schemaOrOptions: SchemaOrSchemaFn<TModel> | FormOptions<TModel>)`, where `SchemaFn<TModel> = (p: SchemaPathTree<TModel>) => void`. The schema-callback parameter type is **`SchemaPathTree<TModel>`** — it is exported from `@angular/forms/signals`. There is no `FieldPath` export in this version.
- ApexCharts (`apexcharts` 5.10.4): the donut total formatter is declared at `node_modules/apexcharts/types/apexcharts.d.ts:996` as `formatter?(w: ApexCharts.ApexOptions & { globals: any }): string`. The `ApexCharts` namespace is globally available with no import.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser SPA -> `aque-backend` REST API | Every request crosses here carrying the `Authorization: Bearer` header injected by `authInterceptor`. This phase changes how the destination URL is *constructed* for all 7 call sites, so the base value becomes a single high-leverage input to that boundary. |
| Build pipeline -> shipped bundle | `angular.json` `fileReplacements` selects which config module is compiled into the artifact deployed to the Pi. Anything placed in an environment file is public in the shipped JS. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `src/environments/environment.ts` / `environment.prod.ts` | high | mitigate | If `apiBaseUrl` were resolvable at runtime from untrusted input (a `window.__env` global, a query parameter, a `localStorage` key), an attacker could redirect every authenticated request — and the bearer token with it — to a host they control. Mitigated by construction: both files export a plain string literal and nothing else, selected at **build time only** via Angular's `fileReplacements`. Task 1's acceptance criteria enforce this with a negative grep for `window`, `localStorage`, `sessionStorage`, `document`, `location` and `process.env` across `src/environments/*.ts`. |
| T-01-02 | Information Disclosure | environment files | medium | mitigate | Environment files are a common place for API keys to accumulate; everything in them ships in the public bundle. Mitigated by scope: the object has exactly one member, `apiBaseUrl`, holding a same-origin relative path. Task 1's action forbids secrets, tokens and keys explicitly. Re-check this at any future edit to these files. |
| T-01-03 | Spoofing | `auth.service.ts` login call | low | accept | The login endpoint URL construction changes but the request body, credential handling, JWT storage (`aque_token` in `localStorage`) and the `authInterceptor` chain are untouched. The pre-existing localStorage-JWT risk is a recorded, accepted decision (PROJECT.md / CONCERNS.md) and is explicitly out of scope for this milestone (REQUIREMENTS.md "Out of Scope"). |
| T-01-04 | Tampering | `login.component.ts` / `dashboard.component.ts` typing changes | low | accept | Both edits are compile-time only. `LoginModel` mirrors the shape the signal already held and `DonutTotalContext` mirrors the library's own declaration; neither alters a validation rule, a request payload, or rendered output. Task 3's acceptance criteria forbid `@ts-ignore` / `@ts-expect-error` / `as unknown`, so the strictness cannot be traded away for a passing build. |
| T-01-SC | Tampering | npm installs | high | accept | No package-manager install task exists in this phase — no dependency is added, removed or upgraded, so the supply-chain surface is unchanged and no package legitimacy audit is required. Enforced by acceptance gate: `git diff --exit-code package.json package-lock.json` must exit 0 at phase end (see `<verification>`). If any task turns out to need a new dependency, stop and route back to planning for a legitimacy audit rather than installing inline. |

ASVS level 1, block-on threshold `high`. T-01-01 is the one `high` threat carrying a mitigation, and its mitigation is enforced by an automated acceptance criterion in Task 1.
